# Nakama Server Module

`src/rules` 是纯规则核心；`src/matches` 和 `src/rpc` 是 Nakama 边界适配器。构建产物只有 `build/index.js`，供 Docker 容器加载。

当前实现工程闭环需要的 30 张牌库、3/4 张起手、回合抽牌、7 张手牌上限、公开爆牌、递增真实疲劳、开局快照、卡牌部署、主行动/战斗阶段、普通攻击、同步反击、死亡离场、英雄伤害/护甲、胜负、结束回合和认输。`PLAY_CARD` 已通过稳定 `effectId` 注册表接入 `熔岩献祭`、`腐肉`、`潜影壳`与首个有目标效果 `雪球`；目标在付款前按敌我关系、对象类型和稳定实例 ID 校验。雪球的临时减攻由权威状态记录，并在施法者回合结束时通过独立事件恢复。其余效果会在支付费用前明确拒绝。战场格保存稳定实例 ID，多格结构的多个格子引用同一个状态对象。抽牌事件按接收玩家单独投影，对手只能看到未知手牌位与区域数量；完整牌库顺序不离开服务端。当前 74 张机制验证卡不足以组成满足同名上限的完整单阵营牌组，因此匹配初始化暂用 30 张可复现的群系测试牌序；构筑校验与起手调度仍待接入。嘲讽、冲锋、其他目标类型与其余具体卡牌效果也仍待实现。新增规则时先写规则测试，再接 Match Handler，避免把领域逻辑写进网络回调。

协议 opcode：`1` 命令、`2` 事件批次、`3` 命令拒绝、`4` 权威快照。协议结构以 `shared-schema/protocol` 为准。

当前基础对局纵向切片使用 `protocolVersion: 5` 与 `rulesetVersion: prototype-0.5`。v2 将战场格内容从卡牌 ID 改为稳定实例 ID；v3 加入私有牌库、抽牌、爆牌与疲劳状态；v4 加入权威 `PLAY_CARD` 与英雄效果事件；v5 加入目标实例与临时属性变更/恢复事件。旧客户端不能静默兼容。

运行：

```powershell
npm test
npm run build
```
