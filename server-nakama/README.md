# Nakama Server Module

`src/rules` 是纯规则核心；`src/matches` 和 `src/rpc` 是 Nakama 边界适配器。构建产物只有 `build/index.js`，供 Docker 容器加载。

先后手由可回放的对局种子决定，不依赖玩家进入房间的先后顺序。

当前实现工程闭环需要的 30 张牌库、先手 3 张/后手 4 张起手、双方各一次任意数量调度、首回合抽牌、7 张手牌上限、公开爆牌、递增真实疲劳、开局快照、卡牌部署、主行动/战斗阶段、普通攻击、同步反击、死亡离场、英雄伤害/护甲、胜负、结束回合和认输。调度时先暂时移出所选卡、抽取等量替换牌，再把原牌洗回隐藏牌库；双方确认前权威状态保持 `MULLIGAN`，普通对局命令不会生效。

稳定 `effectId` 注册表现已接入 26 个效果。`鲑鱼群`部署后可通过公开的水流选择移动到同排相邻空单位格，成功移动后本回合获得 +1 攻击；保持原位不会获得增益。`海豚向导`会监听成功移动事件，每个向导在每个行动回合只强化第一次移动的其他己方生物，使其本回合额外获得 +1 攻击；多个向导按单位格顺序分别触发，回合切换时统一重置。`溺尸`部署到水生友军相邻格且场上存在敌方生物时，必须在付款前提交合法敌方生物目标，部署后造成 1 点伤害并进入统一死亡结算；条件不成立时仍可部署但不要求目标。`守卫者`会在每回合第一次有敌方生物实际移动后对其造成 1 点伤害；多个守卫者按单位格顺序独立触发，保持原位不会消耗响应，被敌方击杀时掉落`海晶碎片`。`海龟`保留嘲讽，并为左右相邻的其他己方生物动态提供可叠加的 +1 当前与最大生命；部署、召唤、移动和死亡都会立即重算，失去光环造成的零生命会进入统一死亡结算。`珊瑚礁`按建筑实例独立强化每个行动回合首次入场的己方水生生物，使其永久获得 +1 当前与最大生命；多个珊瑚礁按建筑格稳定叠加，触发标记在回合切换时重置。`海晶碎片`只能在付款前指定拥有相邻空格的己方水生生物，随后强制选择一个相邻格移动；落位后先重算相邻光环，再恢复 1 点生命，最后依次结算海豚向导与敌方守卫者反应。`激流三叉戟`会进入公开的英雄装备槽；英雄每回合可攻击一次，每次攻击消耗 1 点耐久，攻击生物时承受反击。目标生物存活且相邻存在空单位格时，控制者可在战场地块上选择一次横向位移，也可保持原位；所有位移选择都会锁定其他命令并通过快照恢复。装备替换和耐久耗尽都会将旧装备放入弃牌堆。`流浪者`部署前必须指定敌方生物，战吼施加不减攻击的`缓慢`，被敌方击杀时掉落`骨头`；`粉雪桶`会把同一缓慢状态强化到绑定 -2 攻击，直到目标控制者的结束阶段统一移除。重复施加不叠加，快照和事件都会记录来源、规则绑定值、实际生效修正与剩余持续时间。`可疑的沙子`会将`陶片`洗入隐藏牌库并获得护甲；陶片出土时公开进入手牌（满手则进弃牌堆）、获得护甲，再继续本次正常抽牌；`沙漠考古学家`会私下查看牌库顶三张，只允许拥有者选择其中带掩埋标记的一张出土，选择完成前锁定其他行动；任一方式完成出土后，`恶地劫掠者`在本回合的红石费用由 3 降至 2，回合结束立即恢复。

其余已接入效果包括`蜜蜂`战吼治疗、`沙尘暴`全场生物伤害、`熔岩献祭`、`雪球`、`腐肉`、`骨头`友方临时增攻、`圆石`建筑治疗、`潜影壳`、`潜影贝`亡语与`岩浆怪`亡语。潜影贝死亡时生成 `tk_016`；手牌未满时只向拥有者投影卡牌身份，满手时直接进入公开弃牌堆。岩浆怪死亡时通过公开 `OBJECT_SUMMONED` 生成 `tk_014`，优先占用来源释放的单位格。尸壳、放牧绵羊、地牢骷髅与流浪者仅在被敌方控制的攻击、反击或伤害击杀时，分别向击杀者生成 `tk_005`、`tk_001`、`tk_009` 与 `tk_009`。地牢骷髅先从当前合法敌方生物中确定性选取并记录一个随机目标造成 1 点亡语伤害，再结算自身掉落；亡语造成的新死亡进入下一批检查。

死亡结算会先移走同批双方全部死亡对象，再按当前玩家、非当前玩家顺序处理亡语，并在每批后重复死亡检查；同一控制者的手动排序命令尚待接入，当前按单位格从左到右确定性执行。目标会在付款前按敌我关系、对象类型和稳定实例 ID 校验；临时增减攻由权威状态记录并在所属状态或回合时点通过独立事件恢复。基础关键词 `TAUNT` 与 `CHARGE` 已成为公开战场状态：多个存活嘲讽目标会共同屏蔽英雄和非嘲讽对象，冲锋允许生物在召唤回合攻击。其余效果会在支付费用前明确拒绝。战场格保存稳定实例 ID，多格结构的多个连续格引用同一个状态对象；权威测试覆盖边界/重叠拒绝、攻击只命中一次、结构不反击，以及三格结构死亡后一次释放完整范围。抽牌、调度、生成到手牌和牌库查看事件按接收玩家单独投影，对手只能看到未知手牌位与隐藏的选择占位；完整牌库顺序不离开服务端。当前 74 张机制验证卡不足以组成满足同名上限的完整单阵营牌组，因此匹配初始化暂用 30 张可复现的群系测试牌序；构筑校验仍待接入。当前卡池已有 4 张嘲讽牌，但还没有正式冲锋卡牌；不可指定状态与其余具体卡牌效果仍待实现。新增规则时先写规则测试，再接 Match Handler，避免把领域逻辑写进网络回调。

两名客户端加入 Nakama matchmaker 时必须通过字符串属性 `factionId` 提交七个已注册群系之一。`biomeRivalsMatchmakerMatched` 会校验人数、用户 ID 与群系值，并把用户到群系的映射传入 `nk.matchCreate('biome_rivals')`，确保返回的是权威 Match Handler，而不是同名中继房间。Match Handler 按该映射建立可复现的群系测试牌序，不能根据连接先后猜测玩家阵营。

协议 opcode：`1` 命令、`2` 事件批次、`3` 命令拒绝、`4` 权威快照。协议结构以 `shared-schema/protocol` 为准。

当前基础对局纵向切片使用 `protocolVersion: 21` 与 `rulesetVersion: prototype-0.27`。v21 为永久生命成长补充最终最大生命事件，并允许公开的珊瑚礁每回合触发键；`prototype-0.27` 接入 OR-007 珊瑚礁的水生入场监听、逐实例叠加、回合重置与 Unity 体素建筑反馈。`ATTACK.attackerInstanceId = "HERO"` 继续表示英雄发起的装备攻击。旧规则集客户端不能静默兼容。
