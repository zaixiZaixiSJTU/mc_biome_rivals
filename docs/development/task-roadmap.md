## 执行原则

1. 一个任务只解决一种主要风险，并对应一个可审查提交或一组紧密相关提交。
2. 新会话必须以任务编号开头，只读取本任务列出的入口文件；不要默认加载全部历史。同一任务若同时要求视觉、联机和文档收口，应继续拆分。
3. 未通过任务自己的完成定义前，不启动依赖它的任务。
4. 协议、服务端权威规则、Unity 状态投影和 UI 表现必须按纵向切片一起验收，禁止只在客户端伪造规则结果。
5. 每项测试记录命令、测试层级、通过数量和 Git 提交号；不再只写孤立的 `202/202`。
6. 生成型 Minecraft 资源与来源清单分开管理；是否提交必须服从资源管线约定。
