# Biome Rivals 分阶段任务路线图

更新时间：2026-09-18

本文用于把跨 Unity、权威规则、联机、内容与资源管线的大目标拆成可独立进入新会话、独立验证和独立提交的任务。`change-log.md` 记录已经发生的改动；本文只记录尚待推进的工作与依赖关系。

## 执行原则

1. 一个任务只解决一种主要风险，并对应一个可审查提交或一组紧密相关提交。
2. 新会话必须以任务编号开头，只读取本任务列出的入口文件；不要默认加载全部历史。同一任务若同时要求视觉、联机和文档收口，应继续拆分。
3. 未通过任务自己的完成定义前，不启动依赖它的任务。
4. 协议、服务端权威规则、Unity 状态投影和 UI 表现必须按纵向切片一起验收，禁止只在客户端伪造规则结果。
5. 每项测试记录命令、测试层级、通过数量和 Git 提交号；不再只写孤立的 `202/202`。
6. 生成型 Minecraft 资源与来源清单分开管理；是否提交必须服从资源管线约定。

## P2：联机闭环，先可玩再扩展

### NET-020 Docker + Nakama 双客户端最小对局

状态：**已完成**。`validate-online-demo.ps1` 使用两个真实 Windows Player 完成不同设备认证、不同阵营匹配、起手确认、部署、阶段切换、结束回合、英雄攻击和投降；双方最终收敛到同一 FINISHED revision、胜者与生命值。

### NET-021 断线重连与状态恢复

状态：**已完成**。真实 Windows 双客户端探针会强制关闭其中一端的实时连接，要求其经过 `Reconnecting → Ready`、按原 Match ID 重入并收到新的私有快照，之后双方继续完成整场动作链。服务端允许同一玩家的新 session 原子替换尚未清理的旧 presence；版本不兼容会锁定客户端失败态；重连开始时未确认命令立即按传输失败收束。

依赖：NET-020。

目标：客户端重连后只依赖权威快照与事件恢复，不依赖旧 UI 内存状态。

完成定义：等待选择、隐藏手牌、FIRE 等公开状态、装备与当前行动方恢复正确；重复命令具备幂等性；版本不匹配给出可理解错误。

### NET-022 大厅与账户外壳

状态：**已完成**。账户认证已从实时匹配传输拆出，游客设备会话可跨对局复用；顶部大厅条展示账户、当前原型卡组、连接状态和匹配入口，失败、取消与重试有明确状态。详细边界见 `account-lobby-shell-v1.md`。

依赖：NET-020。

目标：为后续注册、登录、改名、卡组与匹配入口建立可替换边界，不在本任务实现完整商业账户系统。

完成定义：认证接口与 UI 解耦；游客/设备登录可用；配置和密钥不写死；失败、取消和重试状态清楚。
