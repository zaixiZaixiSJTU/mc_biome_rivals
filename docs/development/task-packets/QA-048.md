# QA-048 Unity 网络 JSON null 与真实双 Player 验收

更新时间：2026-10-03

## 发现与修复范围

真实 Unity Player 在协议匹配的隔离 Nakama 服务上能认证/匹配/加入，但两端接收初始快照时均发生 Snapshot contains invalid hand card instances。旧 JavaScript 回手 smoke 通过不能覆盖此 Unity 序列化问题，旧 EditMode 测试也没有将真实 null 手牌实例占位接入完整 StateStore。

新增两项 wire-null 回归先在原解码器中失败（2/2）：对手手牌占位导致 StateStore 拒绝，显式 null handProjection 被实例化为空对象。红测 XML 为 Temp/CurrentUnityCli/qa048-wire-null-red.xml，SHA-256：3CD8F5EC3E2AF8732F8AD1BF5BA240C485408BDA8B65AFAEE75E03442A8B68E0。

- 新增 Networking 的 MatchWireJson：保留 JsonUtility 的 DTO 解码/默认字段行为，再按已安装 Nakama SDK 的匿名 JSON 结构恢复明确的引用 null，包括嵌套对象、引用数组和字符串。不是按 viewer 身份擦除对手数据，真实非空泄露仍由原 StateStore 拒绝；不放宽核心校验。
- 收件的 Snapshot、EventBatch、Rejection 统一使用此边界，移除 pendingChoice 的字符串查找特例。出站命令格式、协议 40、规则集 prototype-0.65、卡牌内容和服务端规则均不变，无新包依赖。
- 匿名结构解析前限制消息为 262144 字符、最大 32 层，检查括号/字符串完整性并忽略字符串中的括号。新增 9 项回归，覆盖完整私有快照、非空泄露拒绝、事件 null、深度边界、尺寸、坏括号、未闭合字符串与真实选择不误清空。
