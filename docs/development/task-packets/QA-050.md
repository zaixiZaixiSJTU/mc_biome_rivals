## 发现与修复

1. 隔离 Compose 容器的 OS 环境开关为 true，但 ctx.env 未配置，实际 opcode 255 请求被服务器拒绝。根 Compose 现在显式使用 Nakama runtime.env 参数映射该开关；默认 false 保持不变，只在独立测试项目覆写 true。依据 [Nakama 官方配置](https://heroiclabs.com/docs/nakama/getting-started/configuration/) 及实际镜像 nakama --help。
2. 首次双 JavaScript 客户端平局探针通过，但 Unity 引擎消费完全相同的真实 wire 失败：Play event hand count does not match projected hand。夹具在权威副本替换了生命/手牌，却只发布普通 PLAY_CARD 的结果批次，客户端不知道被注入的前置状态。
3. 仅夹具路径在规则命令接受且终局校验成功后，先逐玩家发布脱敏前置快照，再发布正式事件批次；不放宽客户端规则、手牌计数、终局校验或生产命令。拒绝时不发布前置快照。前置 ACTIVE/双生命 0 是显式测试条件，不宣称属于当前卡池合法可达玩法。
4. 增强服务端 fixture 回归，检查快照→正式批次→ack 顺序、原状态未被修改、基线 revision 和隐私；另覆盖 runtime gate 只有精确字符串 true 生效，缺失和近似值均关闭。
5. JS 探针记录收到的原始 opcode/JSON 顺序，严格核对当前版本、前置快照、终局 revision 与恢复身份；报告拒绝覆写已有文件，不在 stdout 打印全部私有轨迹。
6. 新增 Editor 专用 DemoWireReplayAudit 和 validate-draw-wire-replay.ps1，把每条实际消息送入生产 AuthoritativeMatchGateway → MatchStateStore，并检查双方各一次前置快照、一次平局事件、最终状态与权威视图。记录源 SHA，拒绝覆写结果、拒绝使用已打开的工程及错版本 Editor。此工具没有直接修改游戏状态，也不从截图推断玩法。
