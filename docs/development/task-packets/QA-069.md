## 只处理这一项

用实际 Unity 引擎检查关闭 `DEVELOPMENT_BUILD` 后，当前 runtime 不引用开发专用接收暂存、测试夹具、在线专项探针或兼容负向审查接口。不是发行批准，也不建立/提交独立 Git 树。

1. 读取 DemoBuildAutomation、Demo/Networking runtime 的条件编译边界与现有来源 manifest 验证；保留现有默认 Development 构建入口。提供明确的非 Development 构建入口和可辨别模式的构建证据，不能只凭 Editor tests 冒称 release 编译通过。
2. 在现有隔离 Unity 工程同步当前源码后构建全新、独立目录的非 Development Windows Player，保存实际引擎编译结果/日志/退出码，任何错误先按原依赖修复，不暴露开发 API 来凑通过。
3. 对编译后的游戏 runtime 程序集检查开发专用接口/类确实不存在；同时正式 Session/Gateway/协议/只读图鉴存在。仅源码 `#if` 搜索或 manifest 模式字段不替代编译产物证据。
4. 如果修改 Assets，原 680 项 Player 立即变为历史证据，重新调用 Unity tests 并构建来源匹配 Development Player；普通联机正/负路径按修改风险复验。不得拿旧 Player 验证当前源码。
5. 记录非 Development 素材/运行限制，但本项不进行发布、资源再分发、资产管线迁移、整包暂存/提交或重启原默认服务。当前 DemoCardArtProvider 的外部 MC 图标读取和复制为开发专用，不能把编译通过称为正式包视觉一致或可发行；如确认实际缺图，另拆素材打包任务处理。
