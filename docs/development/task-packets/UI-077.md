## 源事实与实现边界

- 原 `entity_enderman.tga` 是64×32、未压缩32位TGA。原图有392个不透明纯黑像素，不能把所有黑块称为透明洞。头部正面6个紫色像素alpha=3/255，原统一cutoff=.1会剔除；alpha=0且RGB非零的像素数量为0。Unity导入已为Uncompressed/Point，本轮不改原纹理、模型JSON或导入设置。
- 对照固定Mojang [client entity](https://github.com/Mojang/bedrock-samples/blob/736072450c26a7c67f07b1661f29d9a5ebaa14b1/resource_pack/entity/enderman.entity.json)、[render controller](https://github.com/Mojang/bedrock-samples/blob/736072450c26a7c67f07b1661f29d9a5ebaa14b1/resource_pack/render_controllers/enderman.render_controllers.json)、[animation](https://github.com/Mojang/bedrock-samples/blob/736072450c26a7c67f07b1661f29d9a5ebaa14b1/resource_pack/animations/enderman.animation.json)，确认专用材质和base_pose。PrismarineJS固定版本的通用alphaTest=.1与原始模型并不能直接解决此实体；未复制上游代码或新增依赖。
- 工厂明确登记末影人低alpha发光策略，cutoff=.5/255保留紫眼而剔除零alpha；shader将低alpha RGB近似为发光颜色，opaque原明暗保留。**这是Unity材质近似，不是未读取的Bedrock fragment shader的逐字实现**，其他实体不启用此策略。
- 原body上沿38而head起点24；注册静态站姿head位移+14，内层hat抵消继承位移-14（源像素单位）。Builder仅添加明确登记的骨骼位置偏移，保留源pivot/UV/cube/层级、两侧朝向和待机。**这不是完整Molang base_pose求值，不把reset字段泛化为+14规则**。
- alpha修复的中间r2图眼睛出现在胸口，未通过姿态验收；因此继续添加并验证站姿适配，不用该中间图宣称模型正确。
