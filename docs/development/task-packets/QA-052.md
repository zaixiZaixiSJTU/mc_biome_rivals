## 真实缺陷与修复

原来 Core 已接受非默认 arenaId，但 Scene 在本地启动时已创建标准 4/3 格位；在线快照仅刷新对象/UI，不同步拓扑。新增真实 Scene 回归后，deep_caverns 5/2 和 nether_lava_sea 3/4 均在 RefreshBattlefieldSlots 抛 IndexOutOfRangeException。红测 XML qa052-arena-transition-red.xml，449 passed / 2 failed，SHA-256 59C67276C84757CE1D83764A94B2423DB96B91B1F1434D7839653BD668502D89。

现在 RefreshAll 根据当前有效 MatchView.ArenaId 一起重建世界地表格与 UI 格：

- 保留 ConfigureArena 的构建前锁定；另设明确的 ApplyAuthoritativeArena 入口处理权威对局切换。
- 旧格立即 SetActive(false)，不等待 Player 延迟 Destroy 才停用碰撞；清除选择、高亮、旧格位材质与对象/反馈缓存。生成网格由既有 DemoGeneratedMeshOwner 释放，不手工重复销毁；几何替换后 Physics.SyncTransforms。
- 刷新模型签名，确保相同对象 ID 在新坐标重建；同布局重连不重复重建，断开后恢复本地场地。
- 重建 UI 格时保留所有其他 Canvas 元素的原有层级顺序。首轮图形验收发现将手牌面板提到顶层会遮住状态文字，已修正为在旧格所在 sibling 位置插入新格，并增加顺序断言。
- 两个非默认配比回归覆盖世界/UI 容量、每一格透视射线、无多余旧格、同布局恢复保持同一地表实例，以及离线恢复。每个逻辑格有地表 MeshCollider + InteractionFootprint，双方 14 个逻辑格对应 28 个活跃目标组件，不能把组件数误作逻辑格数。

## 场地验收配置与安全边界

当前产品契约仍是原型 PvP 默认 standard_meadow，没有新增玩家选场/随机或阵营选场规则。

新增服务端审查配置 BIOME_RIVALS_TEST_ARENA_ID，只在 BIOME_RIVALS_ENABLE_TEST_FIXTURES exact-string true 时读取；未知 ID 拒绝，缺省/空值仍标准。客户端 match params、mode 名与阵营不能覆盖场地。服务端单测覆盖七种已登记 ID、关闭/缺失/大小写错误 gate、未知配置与客户端参数忽略。Compose 仅将两项变量映射 runtime.env，生产根默认 gate=false、arena 空。

本项在线玩法仍用正常匹配、MULLIGAN、DEPLOY_CARD、ENTER_COMBAT、ATTACK、END_TURN、CONCEDE 和自动恢复路径，没有 opcode 255 状态注入、手牌/生命/经济改写。fixture=true 只是隔离场地模式配置的保护开关。
