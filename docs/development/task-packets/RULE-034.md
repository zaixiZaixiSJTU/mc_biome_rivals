## 规则来源与已确认边界

- ED-001 原文：“若己方除外区有悬置牌，获得 +0/+2。”它检查战吼结算时**当前**是否存在 `ownerPlayerId` 为己方的公开悬置条目；敌方拥有的悬置牌不满足条件，也不检查本局历史累计数。
- ED-008 原文：“若己方本局已悬置至少 3 张牌，且有空单位格，召唤 8/8 的‘末影龙化身’。”它需要独立的本局累计状态；单位格满时不满足召唤条件，但仍应按已支付/已部署的传送门框架正常完成基础结算。
- DB-008 原文：查看己方牌库顶 5 张，抽取其中 1 张掩埋牌；若没有，则将 1 张绿宝石置入手牌。选择内容不得泄露给对手。
- TK-018 原文：本回合下一次交易费用减少 1，最低为 0。其结算对象必须由 034A 冻结。
- GDD v0.5 §22.2 只规定交易的概念骨架：场上有村民或村民建筑；消耗绿宝石或满足条件；选择一个交易选项。GDD §0.1 把高级交易排除在最小原型之外，但没有列出基础交易的具体选项与费用。

## RULE-034A：交易契约冻结（设计任务）

**当前状态：待产品规则裁决；未冻结前禁止实现交易与 TK-018。**

2026-09-29 已整理一份**非规范性提案** [`../../design/trading-spec-v1-draft.md`](../../design/trading-spec-v1-draft.md)：提供村民资格、每回合次数、绿宝石实例支付、三个固定商品、TK-018 折扣与事件可见性的推荐答案。状态仍为 OPEN；没有改动 GDD、原型卡文本、Schema、运行时代码或实现注册表，等待产品裁决后再生成正式 `trading-spec-v1.md`。

必须逐项明确并同步到 GDD、原型卡表与卡牌文本：

1. 谁能发起交易：控制拥有 `villager` 标签的单位、村民建筑，还是任一条件即可；若多个同时在场，是否均可交易。
2. 交易时机与次数：主行动阶段是否可随时交易，每玩家每回合总次数上限，以及被取消/非法支付是否消耗次数。
3. 交易费用的计量单位：绿宝石牌张数、红石能量，还是各选项自带的卡牌/资源成本；TK-018 的 `-1` 究竟减少哪一个单位。
4. 最小原型的固定选项及精确结果。每个选项须使用已注册卡牌/效果，不引入随机奖池或高级交易。
5. 绿宝石折扣的持有人、持续时间和消费时机：本回合最后一次**成功**交易消费；无合法交易、玩家取消或费用为 0 时如何处理。
6. 交易产物进入手牌时的满手处理、稳定实例 ID、事件与重连投影。

交付物：`docs/design/trading-spec-v1.md`、更新后的 GDD 与原型卡表/TK-018 文本；运行时代码零改动。设计冻结前保留状态为 `OPEN`，不可将 TK-018 标为 `IMPLEMENTED`。

## 实现子任务（均等待 RULE-033；按依赖顺序独立验证）

### RULE-034B 悬置状态/累计数与 ED-001

- 维护公开当前悬置区；按事件中的 `sourcePlayerId` 累计每个已接受的 `OBJECT_SUSPENDED` 事件一次。重复命令因命令幂等/修订校验不得再次计数，Unity 重放同一修订也不得重复应用。
- 同一张基础卡返回并重新部署后会获得新战场实例；其后再次成功悬置会产生新事件并再次计数。已悬置牌返回、弃置或离区不减少累计数。失败目标和未产生 `OBJECT_SUSPENDED` 的命令不计数。
- ED-001 仅在战吼结算时检查是否有己方拥有的当前悬置条目；悬置牌已返回/离开后不得从历史累计数获得加成。
- 覆盖悬置敌方拥有的对象时计入施放者而非拥有者、当前除外区拥有者过滤、重复命令/事件、重部署后的新悬置事件、返回、满手弃牌、死亡/回手不计作新的悬置、双方视角与快照重连。

### RULE-034C ED-008 终局召唤

- 依赖 034B。ED-008 必须使用服务端累计值；达到门槛且有单位空格时召唤注册的 8/8 衍生牌。
- 覆盖门槛未到、单位格空/满、三建筑格合法性、来源/实例唯一、触发顺序、拒绝与原子性、衍生牌资源和内容注册。

### RULE-034D TK-018 交易减费

- 依赖 034A。以稳定手牌实例保存折扣，并严格按冻结的交易单位、玩家归属、回合到期和成功消费定义执行。
- 覆盖费用截零、非持有者不能盗用、非法/取消交易不误消费、下一次成功交易只消费一次、回合结束清理及私密快照。

### RULE-034E DB-008 私密顶牌选择

- 依赖 034D，以确保无掩埋牌的绿宝石兜底确实可用。
- 只允许从顶 5 张中选掩埋牌；服务端持有隐藏选项，对手事件/快照不可恢复未选牌身份；无掩埋牌时生成注册绿宝石。
- 冻结牌库抽取/未选牌顺序、选择提交与取消、牌库不足 5 张、手牌满时的去向、实例 ID 和事件重放。

### RULE-034F Unity 交互与表现

- 依赖 034B–E。复用协议的私密选择 UI，清楚显示 ED-001 当前条件、ED-008 累计进度、可选牌与交易费用；不得客户端伪造权威结果。
- 离线 Demo 与服务端规则同构；Unity EditMode、确定性 Player 互动/截图必须使用本机 Unity CLI/Editor 验收。

### RULE-034G 双端验收与证据收口

- 依赖 034F。Docker/Nakama 双客户端验证规则事件、私密选项、交易消费、重连恢复、回合到期及重复命令原子性。
- 记录 Match ID、双方 revision、测试计数、Unity 版本、Player 画面及哈希；在线测试不可用时只能报告未验收，不能以单元测试替代。
