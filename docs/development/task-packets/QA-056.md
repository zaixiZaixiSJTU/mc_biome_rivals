### r8 已实现的时序修正（以下为原方案记录）

现策略把 unit-occupied 拖到建筑部署之后，逼迫关键单位跨过很长的随机准备阶段；而全程禁止正常 CD-003 消费会导致满手。下一步应把单位占用拒绝移至其合法 UI 部署后最早可支付的 Main 阶段（仍需第二个真实手牌实例与原占位实例检查），不要等建筑完成。

1. 两端分别完成三个单位容量拒绝、同牌真实 UI 末格部署和一次占用拒绝，再写仅包含 matchId/role/revision 的公开单位审查完成标记。
2. 普通准备战斗只在双方单位前缀都完成且网络 revision 已汇合后允许；在此之前可以正常抽牌/消费/部署，但不能触发随机伤害的准备战斗。这使单位占用测试发生在原单位仍存活时，而不是禁用整局本来合法的卡牌。
3. 前缀之后恢复普通 CD-003 消费/准备战斗：此后的合法亡语、支付和死亡可以改变局面，不得被误称为拒绝导致的变化。每次剩余非法建筑/结构命令仍从新的服务器快照建立完整前后基线；建筑实例和完整足迹要维持到最终冻结恢复。
4. 新增引擎时序/公开标记/原实例保护回归；恢复报告对合法 CD-003 单位拒绝的允许集合并保留对应非法卡负控制。重新全量引擎测试、重建来源匹配 Player、新输出目录跑全三容量及普通建筑，不能把 r4 部分成功拼接成当前完整验收。

此方案已在 r8 实现并通过 497 项引擎测试；真实矩阵仍未全过。服务端生产规则、协议、卡组、红石、RNG 与牌序保持原样。若自然准备仍因其他真实规则卡住，基于新日志继续修正常消费策略，而不是修改生产卡池或重跑至绿。
