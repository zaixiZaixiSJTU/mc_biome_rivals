## 已确认根因与实现

本机提取配置/源 provenance 的 `entity_villager_desert` 是 `textures/entity/villager2/biomes/biome_desert.png`，不是完整皮肤。固定官方 commit `736072450c26a7c67f07b1661f29d9a5ebaa14b1` 的 [client entity](https://github.com/Mojang/bedrock-samples/blob/736072450c26a7c67f07b1661f29d9a5ebaa14b1/resource_pack/entity/villager_v2.entity.json) 明确区分 base 与 desert，并实际引用 [villager_v3 render controllers](https://github.com/Mojang/bedrock-samples/blob/736072450c26a7c67f07b1661f29d9a5ebaa14b1/resource_pack/render_controllers/villager_v3.render_controllers.json) 的基础皮肤/群系服装层。另读 v2 controller，但不把未引用的v2当作当前唯一依据。

- 工厂 db_003 新增 `SurfaceBaseTextureKey=entity_villager`，`TryGetSurfaceBaseTextureKey` 提供只读登记查询；原 geometry key/texture key、卡名与注册ID不变。
- 同一个 Entity Shader 网格表面按 UV 合成 skin 与 biome：先计算 source-over RGB/alpha，再保持原 0.1 cutout/像素采样/面光照。其他材质 `_UseSurfaceOverlay=0` 完全走原路径。不是复制膨胀全身网格，也没有改原PNG/TGA alpha或制作替代脸。
- provider 核验两张原纹理存在、atlas尺寸一致、shader拥有合成属性；缺资产或不支持分层明确失败。工厂仍只创建原立方体数量，pf_004 单层不变。
- 图册纹理映射现记录实际 base + biome 两个资源及64×64尺寸。新预览 `-previewDesertVillagerSurface` 仅Development；保留真实部署/待机/原格位射线，脚本校验双沙漠/单预览模式/构建来源。
- 预览首轮发生真实考古选择遮住模型：r1截图虽然材质/射线门禁通过，但**不作为战场外观证据**。仅在空牌库fixture中调用既有合法resolve-choice正常结算，再刷新；未修改卡牌效果/生产逻辑。r2清晰可见双側模型。
