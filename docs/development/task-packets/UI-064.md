# UI-064 结束阶段召唤就绪提示一致性

状态：已完成，已通过隔离 Unity CLI 全量 EditMode 与 Windows Development Player 双分辨率复核。

依赖：ARENA-037D/F、RULE-032 下界要塞、已实现的林地府邸规则。不修改服务端效果、经济、协议或注册内容。

## 问题与实现边界

敌方 `nt_008` 的地表就绪判断曾硬编码 `player == true`，无法显示敌方就绪；`cd_008` 在非拥有者回合误报“单位格已满”。两者还缺少终局门禁。

`DemoSceneController.TryGetEndPhaseSummonReadiness` 统一铭牌与 3D 地表所用的只读判断，使用 `IDemoMatchView`，离线和权威快照共用：

1. 对局结束：不亮，显示“对局已结束”。
2. 非拥有者回合：不亮，显示“等待己方回合”或“等待敌方回合”。
3. 拥有者单位排无空位：不亮，显示“单位格已满”，容量沿用当前场地。
4. 要塞的拥有者公开总红石不足 1：不亮，显示“红石不足”；临时红石也可支付。府邸无红石要求。
5. 当前条件满足：显示“结束阶段就绪”，使用原有 Mansion/NetherFortress 世界地表效果，跨格建筑全部占用地表保持一致。

“就绪”仅表示当前先决条件满足；结束阶段中更早的伤害、死亡或红石消费可能改变结果，实际召唤仍由规则引擎按冻结顺序结算。UI 不花费资源、分配实例或提前召唤。

名称/生命与状态拆成两行；召唤建筑铭牌固定 18 画布单位字号（1280×720 约 12px）、58 单位底板/48 单位文字区，向上扩展以保留手牌托盘净空。其他棋子与北极熊三行修正铭牌保持原行为。
