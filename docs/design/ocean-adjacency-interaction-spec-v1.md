# 海洋相邻站位交互规范 v1

本规范对应 `protocolVersion 21`、`rulesetVersion prototype-0.31` 与内容版本 23。

## 标签与相邻判定

- 服务端规则目录直接注册卡牌 `tags`，条件效果不得通过卡牌 ID 前缀或中文名称推断“水生”等标签。
- 相邻只检查同一控制者四格单位排中 `slotIndex - 1` 与 `slotIndex + 1` 的存活生物；建筑排、跨边界位置和敌方生物均不参与。
- 服务器在扣除红石或材料前完成部署位置、相邻条件和目标实例的原子校验。

## OR-003 溺尸

- 溺尸部署位置相邻至少一个带 `aquatic` 标签的己方生物，且敌方存在存活生物时，命令必须携带一个存活敌方单位目标。
- 部署成功后先公开 `CARD_DEPLOYED`，再通过 `OBJECT_STATS_CHANGED` 对目标造成 1 点伤害，最后进入统一死亡、亡语和掉落结算。
- 没有相邻水生友军，或敌方没有存活生物时，溺尸仍可部署且不要求空目标占位；此时不产生伤害事件。
- 目标或位置非法时整条命令拒绝，不扣费用、不移出手牌，也不创建战场实例。

## Unity 交互

- 普通合法部署格使用中性地表高亮；能够激活溺尸战吼的空单位格使用更高优先级的金色地表高亮。
- 当至少一个激活位置和一个敌方目标同时存在时，右侧材质化面板要求先锁定敌方目标；目标本体通过 3D 地表/模型高亮表示。
- 悬停部署格时明确显示“会造成 1 点伤害”或“仅部署、不触发战吼”，不依靠玩家阅读隐藏状态判断。
- 溺尸战场实体使用玩家本机 Minecraft JAR 中的原版纹理和体素骨架；原始纹理继续保持本地生成、禁止提交。
