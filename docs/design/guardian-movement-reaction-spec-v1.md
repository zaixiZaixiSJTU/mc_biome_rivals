# 守卫者移动反应规范 v1

本规范对应 `protocolVersion 21`、`rulesetVersion prototype-0.31` 与内容版本 23。

## OR-004 守卫者

- 每个存活的守卫者实例独立记录“本回合是否已经响应敌方移动”。同一方有多个守卫者时，它们可在同一次移动后各触发一次。
- 只有单位的 `slotIndex` 实际改变并公开 `OBJECT_MOVED` 时才算移动；在 `MOVE_UNIT` 选择中保持原位不触发，也不消耗守卫者本回合的响应次数。
- 守卫者只响应敌方单位移动，不响应己方移动、部署、召唤、死亡释放格子或界面预览。
- 响应次数使用稳定键 `<guardianInstanceId>:effect.or_004.01` 存入守卫者控制者的 `triggeredEffectKeysThisTurn`，双方结束任意玩家回合时统一清空，保证“每回合”指完整行动回合而非各自个人回合。

## 权威事件顺序

一次成功移动按以下顺序结算：

1. `CHOICE_RESOLVED`；
2. `OBJECT_MOVED`；
3. 移动来源自身奖励，例如鲑鱼群水流的临时攻击加成；
4. 移动单位一方的首次移动增益，例如海豚向导；
5. 敌方守卫者按 `slotIndex`、`instanceId` 稳定排序，各自对移动单位造成 1 点伤害并发布 `OBJECT_STATS_CHANGED`；
6. 统一死亡、亡语与掉落结算。

若较早结算的守卫者已使移动单位死亡，后续守卫者停止响应且不消耗本回合次数。只有实际发布伤害事件的守卫者才写入触发标记，因此客户端可以仅靠事件批次完整重建该状态。致命伤归属于实际造成致命伤害的守卫者控制者。

## 掉落与交互反馈

- 守卫者被敌方击杀时，通过既有 `CARD_GENERATED` 链路向击杀者生成 `TK-012 海晶碎片`；满手时进入公开弃牌堆。
- Unity 在守卫者伤害事件发生时脉冲守卫者来源与受伤单位，并使用短暂的“守卫射线”战场横幅。反馈必须附着于 3D 单位和地表，不新增悬浮网格框。
- 位移选择界面应在敌方存在尚未触发的守卫者时明确显示“移动后将受到守卫者伤害”；保持原位按钮明确表示不会触发。
