# NT-003 烈焰人 / TK-013 烈焰棒：着火状态规范 v1

本规范对应 `protocolVersion 31`、`rulesetVersion prototype-0.48` 与内容版本 40。

## 规则语义

- `FIRE`（着火）默认持续 2 次受影响对象控制者的结束阶段。每次先造成 1 点真实伤害，再将剩余时长减 1；归零后移除。
- 同一对象上的着火不叠加。再次施加时取当前剩余时长与 2 的较大值；只有实际刷新时才替换伤害来源。
- 状态保存来源玩家、卡牌、实例和效果 ID。来源对象离场后状态仍继续；着火致死时，击杀归属于最初施加或最后一次有效刷新的来源玩家。
- 本纵向切片的两个来源都只指定生物；协议与状态容器保留以后让英雄、建筑和结构着火的扩展空间。
- 同一对象存在多个结束阶段状态时，原型继续使用状态数组的稳定顺序；GDD 所述玩家排序窗口留待统一交互实现。

### 烈焰人

- 烈焰人对生物造成大于 0 的普通攻击伤害后，若受伤生物仍存活，则施加 `FIRE 2`。
- 主动攻击与作为防守方反击分别独立检查。烈焰人即使在同次战斗中死亡，已经造成的伤害仍能施加着火。
- 烈焰人被敌方来源击杀时，按现有掉落流程向击杀者生成一张 `TK-013 烈焰棒`；满手时公开进入弃牌堆。

### 烈焰棒

- 只能在主行动阶段指定一个存活的敌方生物；目标与费用均在付款前原子校验，并遵守黑暗的首次敌方战场目标限制。
- 先造成 1 点普通伤害。目标存活时再施加 `FIRE 2`；若该伤害已经致死，则直接进入死亡/掉落链，不创建无意义状态。

## 权威事件顺序

烈焰人造成战斗伤害：

1. `ATTACK_RESOLVED`
2. `OBJECT_STATUS_APPLIED`
3. 同批死亡的 `OBJECT_DIED`、亡语和掉落事件

烈焰棒命中存活目标：

1. `CARD_PLAYED`
2. `OBJECT_STATS_CHANGED`，`reason = DAMAGE`、`damageType = NORMAL`
3. `OBJECT_STATUS_APPLIED`

着火结算：

1. `OBJECT_STATS_CHANGED`，`reason = DAMAGE`、`damageType = TRUE`
2. 非最后一次发送 `OBJECT_STATUS_TICKED`；第二次非致死伤害后发送 `OBJECT_STATUS_REMOVED`
3. 致死时改为进入 `OBJECT_DIED` 与死亡连锁，不再发送计时或移除事件

## Unity 表现与交互

- 烈焰人复用本机 Minecraft Java 资源中的 `entity/blaze.png`，继续由头部与十二根旋转棒构成体素模型。
- 着火对象脚下使用受主相机 MVP 变换的 3D 地表材质，以红橙到金黄的脉冲显示；不创建 Screen Space 覆盖框。
- 对象模型周围附着五束错落的发光体素火苗，随对象一起移动和离场；世界标签显示“着火 N”。
- 烈焰棒沿用统一的卡牌目标控制器：选牌、点击“选择点燃目标”、再点击发光的敌方生物；非法目标不会消耗手牌或红石。
- 权威事件回放区分烈焰棒的普通命中与结束阶段的真实火焰伤害，并在状态施加/移除时播放橙色横幅与场内脉冲。

## 验收矩阵

- 主动攻击与反击均能施加着火，来源烈焰人同次死亡不取消状态。
- 两次控制者结束阶段各造成 1 点真实伤害，状态按 `2 → 1 → 移除` 变化。
- 重复施加刷新但不叠层；状态来源在有效刷新时更新。
- 着火击杀正确传递击杀归属；烈焰人被敌方击杀正确生成烈焰棒。
- 烈焰棒先伤害、后施加状态，致死目标不保留状态。
- 权威服务端、Unity 本地模式、Unity 状态回放、协议 Schema 与双客户端联机使用同一版本组合。
